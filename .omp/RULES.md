# Workshop Hard Requirements

- Never run anything that sends fiscal commands to a real printer (receipts, reports, apps or scripts pointed at a serial port). Exercise printer code through `posnet::simulator::Simulator` and tests; the only allowed real-device command is the read-only `holuto-fiscal --serial <port> --probe`, and only when the user asks. Why: a fiscal receipt or report is an irreversible legal record.
- Preserve the fiscal safety invariants from README "Fiscal safety" in every driver, agent or desktop change: verify the printer state before every operation; journal intent before the first command reaches the printer; never retry a command on the device and never reprint; an uncertain outcome blocks further operations across restarts until a person resolves it, and resolving never reissues anything. Why: breaking any of them can double-print or lose a fiscal record.
- Printer I/O and Holuto requests run only on the single `agent::worker::Worker` thread; the GUI thread only submits commands and receives events. Stop it cooperatively (`Worker::stop`, then `join` after `Event::Stopped`); never block the GUI thread on it and never abandon it mid-operation. Why: a frozen UI invites a second click, and a killed operation leaves an uncertain fiscal outcome.
