# Workshop Hard Requirements

- Never run anything that sends fiscal commands to a real printer (receipts, reports, apps or scripts pointed at a serial port). Exercise printer code through the socket simulator and tests; the only allowed real-device command is the read-only `fiscal-desktop --serial <port> --probe`, and only when the user asks. Why: a fiscal receipt or report is an irreversible legal record.
- Preserve the fiscal safety invariants from README "Fiscal safety" in every driver or desktop change: verify the printer state before every operation; journal intent before the first command reaches the printer; never retry a command on the device and never reprint; an uncertain outcome blocks further operations across restarts until a person acknowledges, and acknowledging never reissues the receipt. Why: breaking any of them can double-print or lose a fiscal record.
- Printer I/O runs only in the desktop app's single `Worker` `QThread`, started with `start()` and stopped cooperatively (`requestInterruption()`); never block the GUI thread and never terminate the worker mid-operation. Why: a frozen UI invites a second click, and a killed operation leaves an uncertain fiscal outcome.
